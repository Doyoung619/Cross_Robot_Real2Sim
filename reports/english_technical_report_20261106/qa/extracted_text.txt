Three separate meanings of success
Teacher success is placement achieved by the executed source-grounded controller. Learned-policy
success is placement achieved by the saved MLP in closed loop on different simulator seeds.
Human-video understanding success would require actual CLIP and Qwen inference on a real
human clip; it is currently untested.

The dataset source is human-operated Panda robot demonstration data, not a video of an unaided
person. The executable Panda scripted branch validates live source control, while the new original-state
source videos reconstruct recorded HDF5 states. These are distinct evidence types.

03 / STAGE 1


Data selection: what actually ran
Fast mode chooses five episodes from the first eight inspected source IDs; it does not search or
rank the entire 200-episode corpus.

Deterministic selection algorithm
1. Enumerate source demos by numeric ID and inspect at most eight candidates (demo_0 through
demo_7). Require nonempty actions and consistent observation lengths; retain the Can/Panda task
provenance.
2. Sort coherent candidates by sample count, breaking ties by demo ID. Select the shortest
demonstration first.
3. Repeatedly select the remaining candidate with the greatest minimum Euclidean
initial-object-position distance to the already selected set. Stop after five selections.

  selected = [shortest_consistent_demo]
  while len(selected) < 5:
      next = argmax_d min_s ||object_start[d] - object_start[s]||_2
      selected.append(next)

05 / STAGE 2


Task understanding: provided semantics
Bootstrap and fast modes validate an explicit task specification; they do not infer goals from
invented video.

Executed task representation

  task_source: provided_seed
  object: can
  goal: {relation: inside, receptacle: bin}
  goal_pose_source: simulator_oracle
  unknowns: {mass: unknown, friction: unknown, contact_state: unknown}


The seed contains eight ordered stages: pre-grasp, grasp, close, lift, transport, lower, open, and retreat.
Constraints require lifting before transport, clearing the source bin wall, and releasing over the assigned
target compartment. Pydantic rejects unsupported object/goal relations and fabricated known physical
properties.

  Semantic label                            Declared simulator binding / assumption


  can                                       Can object in PickPlaceCan. The object identity is fixed for this MVP.


  bin                                       The Can object's assigned target_bin_placements[can_index] entry. The visual
                                            receptacle in a future clip need not look identical.


  Metric object and target poses            Read from privileged simulator state; no metric 3D position is reconstructed from
                                            monocular video.


  Mass / friction / contact in task         Remain unknown. Simulator contact used by controller/features is a separate
  JSON                                      privileged observation, not an inferred human-video contact fact.



Interface to retargeting
task_spec.json includes schema version, seed, mode, task source, model/controller name, input IDs,
units, privilege flags, semantic mapping, and assumptions. Stage 3 validates the task before collection
and refuses unsupported semantic mappings. The controller still implements only the fixed
can-inside-bin scenario; it is not a general task planner.

06 / STAGE 3, SOURCE GEOMETRY


What crosses the embodiment boundary
The source contribution is a measured grasp offset and lift clearance, not a copied joint
trajectory or a learned source policy.

Schema discovery matters
For the actual 14D object observation, indices 0:7 contain EEF-relative pose; world can position is 7:10
and world quaternion is 10:14. Treating the first three values as world XYZ produces physically
implausible geometry. The adapter explicitly decodes and tests this layout. EEF pose and actions are
read from their named datasets. Timestamps are reconstructed from the recorded 20 Hz control rate.

Extraction and calibration

  r[t] = eef_position[t] - can_world_position[t]
  closing = {t : recorded_gripper_action[t] > 0}
  grasp_t = argmin_t_in_closing ||r[t]||_2
  grasp_offset = r[grasp_t]
  source_lift = max_t can_z[t] - can_z[0]


When closing actions are absent, a geometric nearest-approach fallback is explicitly labeled. The target
clips XY offsets to +/-25 mm and Z offset to [-15,40] mm. Lift is clipped to [0.12,0.25] m and combined
with the configured minimum clearance. Object-relative axes remain world-aligned for the cylindrical
can; this is a translation-relative construction, not a full rotating object-frame motion transfer.

  demo_3                   [4.71, -2.26, 22.81]                              0.20135


  demo_5                   [-10.33, 1.90, 14.24]                             0.25000 (source lift 0.27388)


  demo_7                   [-11.30, 0.03, 8.64]                              0.22358


  demo_4                   [-0.98, -0.09, 12.82]                             0.21071

   Scientific limit / P02
   The overall phase sequence, target generation, gripper timing, and orientation handling are
   hand-coded. Source quaternions may be stored, but their full time-varying orientation is not
   transferred. No source-parameter ablation has isolated the benefit of the source information.

The teacher action is normalized XYZ = clip(0.6 * (waypoint - EEF) / 0.05, -1, 1), with positive gripper
closure during close through lower. The phase tracker is computed online from simulator observations
and elapsed phase steps. It is shared with policy evaluation, making this a hybrid learned-controller
system rather than an autonomous learned phase planner.

Executed outcomes and retained provenance
Fast mode executed one scripted Panda success and ten source-retargeted UR5e successes. Bootstrap
executed one scripted Panda success and three source-retargeted UR5e successes. The separate
target_scripted_bootstrap fallback had zero attempts in these runs; therefore no source-versus-oracle
comparison was performed. Attempt rows retain seed, source ID, origin, placement error, lift, and
failure code.


   Code does not prove physical infeasibility / P05

Filtering and separation
The dataset builder accepts success=true, robot=UR5e, and teacher_origin in {source_retargeted,
target_scripted_bootstrap}. Failed episodes, Panda episodes, learned-policy review rollouts, and any
episode whose seed overlaps held-out evaluation are excluded or rejected. A zero-success dataset
yields blocked_insufficient_teacher_data instead of invented training arrays.

Normalization mean and standard deviation are fitted only on accepted training rows; standard
deviation has a 0.001 floor. The same statistics are saved with the model. Per-episode origins, source
IDs, seeds, sample counts, and paths remain in dataset_metadata.json.


   Known conditioning gap / P06
   Source-specific grasp offset, lift clearance, and the current waypoint are not explicit components of
   the 26D input. They vary across teachers; evaluation uses the first successful teacher's tracker
   parameters. The structural mismatch is verified, while its contribution to the failure remains a
   hypothesis.

09 / STAGE 4, MODEL AND LOSS


A small behavior-cloning model
The first learned target policy is deliberately low-dimensional; ACT, SmolVLA, and RGB policy
learning are outside the executed baseline.



  26D state                           MLP 26-128-128-4               4D intermediary               7D OSC vector
  Training-only scaling               XYZ + gripper logit            Clip XYZ; threshold grip      XYZ / zero rot / grip




  Setting                           Fast baseline value


  Network                           26 input features -> Linear 128 + ReLU -> Linear 128 + ReLU -> 4 outputs.


  Outputs                           Three normalized XYZ regression values and one gripper logit. XYZ is clipped; logit >= 0
                                    closes, otherwise opens.


  Optimizer / budget                Adam; learning rate 0.001; 2,000 updates; batch size 128; training seed 42; gradient
                                    norm clipped to 10.


  Loss                              L = MSE(predicted_XYZ, executed_XYZ) + 0.1 * BCEWithLogits(gripper_logit, close_label).


  Class weighting                   Positive-class BCE weight = (# open / # close), clamped to [0.25,4]; computed only from
                                    training rows.


  Checkpoint                        Model weights, model dimensions, optimizer, normalization, dataset provenance, step,
                                    CPU/CUDA/sampling RNG states.



Action adapter and units
The intermediary is not sent directly to robosuite. BASIC/OSC_POSE expects seven values: XYZ delta,
three orientation deltas, and the gripper command. The adapter uses the installed composite
controller's create_action_vector API, verifies 6D arm control and 7D environment action dimensions,
inserts zero orientation deltas, and clips normalized values. Each XYZ unit maps to 0.05 m per control
step in the tested controller.

Zero orientation delta holds the controller's initial orientation. BC does not learn orientation motion.
Fresh-process evaluation loads the saved checkpoint and the same normalization and feature builder;
training loss alone is never treated as task success.

Observed final losses: fast 0.000499 after 2,000 updates; bootstrap 0.002245 after 300 updates. These are fitting
diagnostics, not independent control-performance measures.

What is measured
Each episode executes the learned XYZ/gripper outputs through the same action adapter and online
phase tracker. The original goal predicate delegates to installed robosuite _check_success(). Mean
placement error is the final can-to-target XY distance; it is not a full 3D pose/orientation score. Fast
baseline success is 9/10; all-episode mean XY error is 81.55 mm, dominated by failed seed 10000.
Success-only mean is 6.53 mm.

Stronger review predicate is separate / P09
Later review re-executes the frozen policy and checks the specific Can inside its assigned
compartment, no grasp contact, and one additional second under the same policy. No scripted override
assists the learned rollout. These stability annotations supplement rather than overwrite the original
evaluation. Review videos and NPZ are excluded from training.


   Evaluation limits / P07
   Ten simulator seeds and one training seed do not establish broad generalization. The policy
   depends on exact simulator state and a manual phase tracker. No unseen object class, task family,
   camera estimator, physical robot, or perception robustness result is available.

Executed intervention
After observing learned-policy failures, select a feasible successful source-retargeted teacher origin,
collect bounded additional trajectories on training seeds distinct from the evaluation set, merge
successful data with the original teachers, retrain BC, and evaluate on the same held-out seeds.
Baseline and corrective fast models each use 2,000 updates; bootstrap uses 300 updates. The
intervention does not directly query or add the failed held-out trajectory to training.

The fast failure at seed 10000 remains. A bootstrap failure at seed 10002 changes to a stable reviewed
success. Additional data and retraining have not been isolated using a retraining-only control. The
already-inspected held-out seeds are appropriate for a debugging before/after comparison, while final
method selection requires a separate untouched evaluation set.

The source-grounded teacher succeeds from the same initial features. Therefore the learned failure
does not demonstrate an unreachable physical target. The policy approaches but settles outside the
phase transition threshold, so no subsequent grasp/lift sequence begins. Both checkpoints show this
symptom.

Two testable hypotheses, not established causes
Conditioning mismatch: five teacher-specific grasp/clearance settings are pooled, but the policy
input does not explicitly include those parameters or the waypoint. Evaluation uses one fixed
parameter set.
Distribution shift: initial object_x and goal_minus_object_x are outside the full training feature range
in the reviewed failure; the largest initial absolute z-score is 7.55 on object_minus_eef_y. Range/z-score
observations alone do not establish causality.


   Next controlled comparison
   Compare fixed-parameter teachers, parameter-conditioned BC, and the existing mixed-teacher
   baseline at equal training budget. Log waypoint error, XYZ outputs, normalized features, and phase
   transitions over time. Keep seed 10000 as a regression case; evaluate final gains on new
   untouched seeds and multiple training seeds.

17 / REPRODUCIBLE EXECUTION


SSH-safe runs and exact artifacts
The runnable baseline is detached; report and media generation do not replace actual
training/evaluation evidence.


  cd /home/dheo/Cross_Robot_Real2Sim
  bash scripts/setup.sh
  bash scripts/preflight.sh
  bash scripts/launch.sh bootstrap
  bash scripts/status.sh RUN_ID
  tail -f runs/RUN_ID/logs/pipeline.log
  bash scripts/resume.sh bootstrap RUN_ID
  bash scripts/stop.sh RUN_ID


launch.sh creates a detached tmux session with absolute project paths, activates the project
environment inside it, exports CUDA_VISIBLE_DEVICES=0 and EGL settings, and stores run/session/PID
metadata. Logs include timestamps. A project GPU lock prevents unintended concurrent project
launches. tmux survives SSH/VS Code disconnection while the host stays running; it is not host-reboot
persistence.

The supervisor uses pipefail so tee does not hide a failed pipeline, records an exit code, handles signals,
and preserves artifacts for resumption. Status checks both live process/session identity and persisted
outcomes; disappearance alone never means success. Resume validates frozen configuration,
input/artifact hashes, JSON/NPZ/checkpoint readability, and seed splits.

Dependency and artifact reproduction

  bash scripts/launch.sh fast
  # Real human input later:
  cp /path/to/real_human_can_clip.mp4 data/human/
  bash scripts/setup.sh full
  bash scripts/launch.sh full
  # Rebuild this PDF, without retraining:
  .venv/bin/python -m pip install -r requirements-report.txt
  .venv/bin/python scripts/build_english_report.py


Simulation, optional perception, review plotting, and PDF dependencies have separate requirement
files. Original environment snapshots and lockfiles remain historical evidence. Raw
runs/checkpoints/datasets stay local and gitignored; compact metrics, manifests, selected videos, and
this report are versioned.

What to trust, what to test next
The evidence supports an honest baseline and specific next experiments, not an
already-complete general real-to-sim method.


  Verification area                      Executed evidence / remaining boundary

                                         missing-human behavior; artifact contracts.


  Simulator and controller tests         Headless Panda/UR5e steps and render; native goal predicate; action
                                         dimension/clipping; seeded reset and frame transforms.


  Learning and diagnosis tests           Shared online 26D feature contract; successful-teacher filtering; held-out seed
                                         separation; saved-policy normalization/load; optimizer/sampling-state resume;
                                         actual-state diagnostic cases.


  Runtime and integration tests          Isolated tmux process fixtures verify detached launch, duplicate-run prevention,
                                         nonzero exit preservation, scoped stop; missing-human full pipeline skips training.


  Report QA                              Embedded DejaVu fonts, English text extraction, page count, text margin bounds,
                                         layout audit, and rendered contact sheets. Report QA is not a new robotics
                                         experiment.



A prioritized experimental sequence
First: resolve the pregrasp stall with equal-budget fixed-parameter versus parameter-conditioned
policies, plus a retraining-only control.
Second: isolate source-information value with source-on/source-off/mismatched-source ablations
under matched target starts.
Third: validate real human input end to end and only then expand evaluation seeds, training seeds,
state-estimation conditions, and physical-robot claims.
