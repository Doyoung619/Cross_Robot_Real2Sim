# 현재 문제 명세 — Cross-Robot Real2Sim

기준 실행은 `fast_20261105T182127Z`, `bootstrap_20261105T181834Z`이다. 이 문서는 관측된 실패, 구현상 제약, 아직 하지 않은 검증을 구분한다. 2026-11-05 리뷰 영상은 기존 제어기와 체크포인트를 재실행한 것이며 신규 학습을 하지 않았다. `full`의 사람 영상 처리 성공 사례는 없다.

## 확인한 결과와 판정 기준

|---|---|---|

| fast 초기 학습 정책 | 9/10 성공 | 평가 10건 모두 재실행, 성공 9건 모두 영상 저장 |

## P01 — 초기 접근 단계에서 학습 정책 정지

**기대 동작:** 손이 캔 위 접근 목표에 도착하면 잡기 단계로 전환하고 캔을 들어 목표 칸에 놓는다.

**실제 관측:** fast 평가 시드 10000에서 피드백 전·후 모두 300스텝(15초) 동안 `pregrasp`에 머문다. 캔의 최대 상승은 약 0.062mm이고 잡기 접촉이 없다. 같은 초기 특징값에서 원본 정보 기반 교사는 배치에 성공한다.

| 측정 | 피드백 전 | 피드백 후 |
|---|---:|---:|
| 마지막 기록 스텝의 접근 목표 오차 | 약 66.2mm | 약 55.3mm |
| 접근 → 다음 단계의 오차 임계값 | 28mm | 28mm |
| 최종 캔-목표 XY 오차 | 약 756.7mm | 약 756.7mm |
| 관측된 단계 | `pregrasp`만 | `pregrasp`만 |

**근거:** [같은 시드 교사/정책 비교 영상](videos/04_failure_teacher_vs_policy.mp4), [수치 증거](problem_evidence.json), 원본 `runs/fast_20261105T182127Z/04_policy/eval_rollouts/eval_10000.npz`와 피드백 후 대응 파일. 영상 재실행의 원래 종료 지점은 기존 성공·실패 기록과 일치한다.

**확정하지 않은 것:** 관절 한계, 충돌, 물리적 도달 불가능이 원인이라고 확정할 수 없다. 이 사례에는 보고된 arm collision이 없고, 같은 조건의 교사가 성공한다. 분포 차이와 교사 조건 정보 누락은 후속 검증 대상이다.

**다음 조치:** 접근 중 목표-손 오차, XYZ 출력, 정규화 입력, 단계 전환을 시간축으로 비교한다. 학습 데이터의 접근 말기 상태를 추가할 경우 평가 시드와 훈련 시드를 분리한다.

**완료 조건:** 기존 실패 시드는 진단 회귀 사례로 따로 보고한다. 개선 방법 선택 후 새로 정한 별도 평가 시드 집합에서 반복 측정하고, 접근 완료율·최종 배치율·기존 성공 사례의 성능 저하를 함께 기록한다. 시드 10000 하나의 성공만으로 일반화 개선을 주장하지 않는다.

## P02 — retargeting 범위 제한 및 원본 효과 미분리

**구조:** `source_trace.py`가 잡기 시점의 손-캔 상대 위치와 캔의 최대 상승 높이를 추출한다. `waypoints.py`는 이를 제한 범위로 보정한다. `controller.py`의 접근·잡기·들기·운반·놓기 순서와 목표 생성은 규칙 기반이다. 손 방향은 초기 자세를 유지한다.

**현재 성공의 의미:** 원본 Panda 데모에서 추출한 일부 정보를 쓰는 UR5e 규칙 제어의 배치 성공이다. 원본 전체 동작·시간 변화·자세 궤적의 자동 변환 또는 학습된 원본 정책의 전이를 검증한 결과가 아니다. 영상의 Panda 분기도 별도로 실행한 scripted 정책이며 HDF5 전체 궤적 재생 영상이 아니다.

**근거:** `src/cross_robot_real2sim/stage3_retarget/{source_trace,waypoints,controller}.py`, 원본 `03_retarget/stats.json`. fast에서 독립 `target_scripted_bootstrap` 분기는 0/0으로 비교하지 않았다.

**다음 조치:** 같은 시작 배치와 동일한 제어기에서 원본 파라미터 사용/미사용, 필요하면 다른 원본 데모 파라미터 사용을 비교한다. 전체 움직임을 옮길 목표라면 물체 기준 전체 위치·자세 경로와 단계별 시간 정보를 추가하는 별도 설계가 필요하다.

**완료 조건:** 조건별 시드·시도 수·배치율·위치 오차를 별도로 공개하고, 원본 정보를 사용한 효과와 규칙 제어기 자체의 효과를 구분할 수 있어야 한다.

## P03 — 사람 영상 경로 미검증

**설계:** `bootstrap/fast`는 제공된 작업 명세를 사용한다. `full`은 실제 사람 MP4에서 CLIP 선택과 Qwen 작업 추출을 실행한다. 사람 영상은 작업의 의미·순서·제약을 제공하고, 수치 로봇 동작 정보는 공개 Panda 데모에서 얻는 구조다.

**관측:** 실제 사람 영상이 없다. CLIP/Qwen 모델 추론은 미실행이며 SAM2는 선택적 미구현 항목이다. `full_20261105T182257Z`는 `partial` / `requires_human_video`이고 retargeting·학습을 건너뛰었다. 현재 schema와 매핑은 can-inside-bin 한 작업에 제한된다.

**완료 조건:** 실제 사람 영상의 출처와 파일 해시를 기록하고, 사용 프레임·CLIP 점수·Qwen 원문·검증된 작업 JSON을 저장한다. 사람이 의미 추출을 검토하고 해당 JSON이 후속 제어 입력에 사용됐음을 확인한다. 이 검증 전에는 사람 영상 기반 전체 성공이라고 표시하지 않는다.

## P04 — 추가 데이터 수집이 fast 실패를 해결하지 못함

**관측:** fast는 성공 교사 3개를 추가하고 동일한 평가 시드에서 재학습했지만 9/10 → 9/10이다. 전체 평균 XY 오차는 81.55mm → 84.58mm, 성공한 9건만의 평균은 약 6.53mm → 9.89mm다. 시드 10000은 그대로 실패한다. 반면 작은 bootstrap에서는 0/3 → 1/3이며 시드 10002 한 건의 실패 → 성공이 재현됐다.

**구조:** 기존 개입은 새 훈련 시드 542–544의 교사를 추가한다. 실패한 접근 말기 상태를 직접 겨냥한 개입이라는 근거는 없다. 추가 데이터와 재학습의 효과를 분리한 대조군도 없다.

**근거:** 원본 두 실행의 `05_diagnosis/before_after.json`, [bootstrap 전후 영상](videos/02_pipeline_bootstrap_feedback.mp4), [문제 수치](problem_evidence.json).

**다음 조치:** 접근 말기 상태 보강, 교사 조건 고정/명시, 재학습만 한 대조군을 같은 훈련 예산으로 비교한다. 피드백 선택에 이미 사용한 시드는 최종 독립 테스트 성적과 구분한다.

**완료 조건:** 같은 평가 시드의 전후 결과를 유지하면서, 독립 시드 집합에서도 성공률·오차 개선 및 실패 유형 변화를 보고한다. 효과가 없으면 `improvement_claimed=false`를 유지한다.

## P05 — 도달 불가능과 접근 미완료의 혼동

**관측:** `rollouts.py`는 종료 시 phase가 0 또는 1이면 `unreachable_waypoint`라고 기록한다. IK의 불가능 판정이 아니다. 시드 10000에서 같은 초기 특징값의 교사가 성공하는 증거가 있다.

**현재 보존 방침:** 과거 CSV는 원본 그대로 두고 이 명세와 비교 영상에 의미를 설명했다. 아직 기본 실패 코드 자체를 변경하지 않았다.

**완료 조건:** 향후 새 schema에서는 `waypoint_not_reached_by_horizon` 같은 관측 코드와 입증된 kinematic infeasibility를 분리한다. 명시적 근거가 없으면 reachability 원인을 `unknown`으로 둔다. 과거 파일은 변환 이력 없이 덮어쓰지 않는다.

## P06 — 교사의 조건 파라미터와 학습 입력 불일치 가능성

**구조 확인:** fast의 교사 데모 5종은 서로 다른 grasp offset과 clearance를 사용한다. clearance는 약 0.201–0.250m이다. BC의 26차원 입력에는 해당 파라미터나 현재 목표 waypoint가 명시되어 있지 않다. 평가용 단계 추적기는 첫 성공 교사의 파라미터를 사용한다.

**가설:** 서로 다른 교사 목표가 하나의 정책에 충분한 조건 정보 없이 섞이면, 원하는 접근 높이에서 행동이 수렴하지 않을 수 있다. 현재 실패의 원인이라는 인과 검증은 하지 않았다. 실패 초기 입력의 일부 특징이 전체 훈련 특징 범위 밖이라는 관측도 있으나 이것만으로 원인을 단정할 수 없다.

**근거:** [problem_evidence.json](problem_evidence.json)의 `teacher_conditioning`, `distribution_observation`; `controller.py:FEATURE_NAMES`와 `stage4_policy/run.py`의 파라미터 선택.

**완료 조건:** 먼저 모든 교사 파라미터를 하나로 고정한 모델과, 파라미터를 입력으로 제공한 모델을 같은 훈련 예산·시드에서 비교한다. 관측 차원·정규화·온라인 단계 추적기의 정의를 학습·평가 양쪽에 동일하게 저장하고 검증한다.

## P07 — 제한된 평가와 privileged state 의존

현재 fast 결과는 한 훈련 시드와 같은 PickPlaceCan 환경의 평가 시드 10개다. BC 입력에는 정확한 손·물체·목표 좌표, 시뮬레이터 잡기 접촉, 규칙 기반 phase가 들어간다. 카메라 기반 정책, 다른 물체·작업·로봇 또는 실제 로봇 성능으로 확대 해석할 수 없다. 1,620개 상태-행동 행은 독립적인 1,620개 시연이 아니라 10개 성공 궤적의 시간 샘플이다.

**완료 조건:** 주장을 확장하려는 범위에 맞춰 새로운 평가 시드와 여러 훈련 시드, 보지 않은 초기 배치 및 원본 데모를 구분한다. 영상 기반 주장은 상태 추정 경로를 실제로 평가하고, 실제 로봇 전이는 별도 실험으로 보고한다.

## P08 — 영상만으로 결과를 오해하기 쉬운 기본 출력

기존 `evaluate.py`는 첫 평가 시드만 렌더링하며 그 시드가 10000의 실패였다. 기존 비교 영상은 224×224 패널에 목표 칸 표시가 없고 짧은 종료 모습만 보여 준다.

**이번에 보완한 것:** 평가 10건 전체 재실행, 성공 9건 전체 모음, 개별 640×480 영상, 한국어 역할/시드/상태 표시, 목표 칸 테두리, 같은 정책의 종료 후 1초 검사, 5단계 증거 영상, 실패 비교 영상. 다른 패널이 끝나 정지 프레임을 보여 줄 때는 종료 표시를 붙인다.

**남은 완료 조건:** 앞으로 새 pipeline 실행에서도 대표 성공·실패와 전후 동일 시드를 자동 선택하고, 렌더 예산 내에서 영상과 CSV의 episode ID가 일치하도록 기본 exporter와 연결한다. 현재 추가 리뷰 도구는 기본 실행과 별개다.

## P09 — 원래 성공 판정의 범위

기본 `goal_success()`는 설치된 robosuite의 `_check_success()`를 호출한다. single-object 모드의 native 판정은 전체 object 목록 중 조건을 만족하는 것이 있는지 검사하며, 성공 직후 추가 안정성 시간을 요구하지 않는다. 현재 Can-only 장면에서는 이번 재검증에서 Can 자체의 목표 칸과 접촉 해제를 따로 확인했다.

**완료 조건:** 기본 평가에도 대상 Can 지정, 목표 칸 내부, 그리퍼 접촉 해제, 설정된 시간 동안의 안정 배치를 함께 기록한다. 기존 native 판정과 강화된 판정을 별도 필드로 유지해 과거 성적과 비교할 수 있게 한다.
